## Decisions to obtain and record explicitly

1. Controlled SOP register: titles, revisions, effective dates, authority matrix and required records/signatures/retention. Existing business-role examples are not the actual Role union or approved permission policy.
2. Inventory: approved openings/import period/location, duplicate source identities and missing Packing/ink openings; material batch supplier/receipt authority; negative/unknown-stock handling; WIP issue/consumption/return accounting; approved adjustments and reversals.
3. Production: mixed stock/manufacturing parent scope, standalone production-for-stock, additional issues after start, excess output decisions, order amendments, partial production/run-to-lot identity, interstage conversion/yield and losses.
4. Quality: original photographs/checklists and document codes, KSEC, approved tolerances/sampling, raw conditional acceptance/partial release/return/destruction, exact final FG managerial role, concession/recall and escalation.
5. Commercial: customer/prospect promotion authority, sales approval/self-approval policy, frozen vs latest model checks, valid acceptance evidence/expiry/tolerance/credit/advance terms and authoritative numbering.
6. Financial: actual transaction currency pairs, LED net-selling vs production-cost percentage base, applicability/eligible KG/VAT-on-LED, quantity/price/FX/rounding precision and source purchase VAT basis. Source code labels MAX as client-confirmed; that is recorded secondary evidence, not an independently reviewed legal tax rule. UGX18% example defaults must not become universal rules.
7. Finance/integrations: fiscal document jurisdiction/authority verification, Tally/EFRIS responsibility, invoice numbering/credit-note/cancellation and payments/expenses scope. Missing screens require separate requirements before endpoints.
8. Deployment: tenancy/company scope, warehouse defaults, Android support, session/token strategy, permission-based document projection, evidence storage, email/provider/public-link scope and schedule worker/calendar.

For each answer record decision ID, source SOP/paragraph or written client approval, effective version, affected model/action/frontend consumer and acceptance test. Keep unresolved decisions as configuration gates; do not silently bake them into migrations. Foundation can proceed while these are pending; production posting cannot be certified.
